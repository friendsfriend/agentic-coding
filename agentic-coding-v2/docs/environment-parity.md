## Exact-content configuration promotion

`POST /api/environments/drafts/promote` writes the exact staged configuration document to the live `environments.json` once the developer supplies that content's digest as an explicit approval and the draft's stored revision/digest still match. Preconditions: native v1 schema acceptance within 32 projects / 128 targets, every referenced repository already authorized and present at its real path, destination absent or a regular file (never symlink/directory) of at most 64 KiB, and a destination outside every authorized repository. Identical live bytes short-circuit to `unchanged` with no write.

The replace is an exclusive same-directory temp file (`0600`), fsync, rename and best-effort directory fsync, with the temp file removed on every failure path and a no-follow digest read-back afterwards. The fence compares the destination base recorded with the draft against the live destination immediately before the write, inside a cooperative cross-instance directory lock (`mkdir`-acquired, release attempted on normal exit, no automatic reclaim). That lock serializes cooperating app instances only; it is not an OS lock, so a non-cooperating writer can still lose an update. A failing read-back records nothing and leaves the fence refusing further attempts rather than restoring bytes that could clobber a concurrent writer. Each outcome is kept as immutable promotion history (at most 64, readable by `promotion-…` id, surviving draft deletion) with explicit `sourceFilesWritten`, `repositoriesChanged`, `runtimeChecked` and `reloaded: false` flags; exact retries replay the record without writing.
