Credentials travel as redacted `-c http.extraheader` argv and never appear in a response, a recorded command or a diagnostic (`test/integration-services.test.ts`, `test/integration-private-api.test.ts`).
- [x] 2.2 Port Git repository/status/branch/worktree reads with canonical-checkout fixtures.

The `worktree-lifecycle` fixture pins the create/list/remove sequence and the primary-removal error, so a workflow pin is never retargeted by a linked-worktree operation.
- [x] 2.5 Connect Go action callers through private adapter with exactly-once command accounting and no route recursion.
  - `server/pkg/integrations` implements the Go client and a `ForwardingRunner`: a `git` command step with a directory crosses the adapter, every other command runs locally, a failed bridge never silently reruns the command, and cancellation propagates. `CommandSpec` now carries the run/step/command identity, set by `CommandHandler`, and `handlers_action_definitions.go` selects the forwarding runner only when the Bun owner advertises the adapter (`DEVENV_INTEGRATIONS_URL`), which `server-command.ts`/`src/tui/index.tsx` pass only when Bun actually serves the Git capability. The action owner still emits the command events and records the run tree, asserted by `server/pkg/integrations/runner_test.go` (exactly one started/output/completed event per forwarded command) and by the private-path test that answers with a dead delegation target.

## 3. GitHub and GitLab

- [x] 3.1 Port GitHub issue reads/search/filter/paging and linked-reference queries.
  - `src/server/integrations/github-issues.ts` + `issues.ts` port list/detail/comments/mutations/labels/collaborators and the linked-reference queries; `github-client.ts` gained the shared authenticated request, owner/repo extraction, Link-header pagination and sorted query parameters. `github-routes.ts` serves the 14 issue routes with the Go status codes and diagnostics, and the `github` family in `LEGACY_ROUTE_OWNERSHIP` is now `bun`. Filtering/search/sort happen before pagination in the provider query (scope becomes a search qualifier, labels become `label:` qualifiers) and the search total replaces the page count; `state=all` falls back to the list endpoint because search cannot express it. 18 issue fixtures replay the whole Go flow (requests, bodies, parsed value) including a pull request filtered out of the issue list, timeline merging and the unreadable-timeline path.
- [x] 3.2 Port GitHub issue mutations and label/assignee/comment operations with no blind POST replay.
  - Mutations patch/put/post exactly as the Go client did (close sends `state_reason` only when a reason is given, unassign sends an empty `assignees` list, a rejected comment reports the provider status instead of a created comment) and re-read the issue only where Go did. A mutation is never replayed against a second runtime: the parity evidence is the recorded fixture flow, and a provider failure surfaces as the Go diagnostic (`Failed to set labels: GitHub API error (status 422): …`).
- [x] 3.3 Port GitHub change-request/diff/discussion/approval operations preserving position/version identity.
  - `github-changerequest.ts` ports list/detail/changes/discussions/approve/unapprove/toggle/close/rebase/diff-comment/reply/resolve with the GitLab-shaped payloads the TUI consumes. Diff position identity is preserved: each file keeps added/removed/renamed identity, `a_mode`/`b_mode`, and positioned diff lines with the Go line code (`sha1("github:<path>:<old>:<new>")`); an inline comment sends the head commit, path, side and line derived from the position. Review threads keep replies attached to their root, timeline events become system notes without duplicating `commented` events, and rebase/resolve answer with the Go "not supported" diagnostics. Approvals count only the latest review state per user and are sorted by username (the Go client iterated a map, so its order was incidental; the fixtures are captured sorted and the port sorts).
- [x] 3.4 Port GitHub CI job/test/log queries and supported controls/streams.
  - Job listing maps workflow-run jobs onto the GitLab job shape (status mapping, duration only when both timestamps are non-zero), job logs follow the provider redirect without the API credential, restart/cancel use the documented endpoints, and the test-summary route reproduces the Go handler's check-run summary extraction (regex order and the `"passed: 3 failed: 1"` quirk included, pinned on both sides by `server/pkg/server/test_summary_test.go` and `test/integration-github-routes.test.ts`). Fixtures cover jobs, the redirect path, and an empty summary when the run or check runs cannot be read.
- [x] 3.5 Port GitLab issue reads/search/filter/paging and linked-reference queries.
  - `gitlab-issues.ts` + `gitlab-routes.ts` port list/detail/notes, labels/members and the linked-reference queries with the Go envelopes and diagnostics. Scope maps to GitLab's underscore values (`assigned_to_me`, `created_by_me`) and `no-assignee` to `assignee_id=None`; the state is normalized to `opened`; totals come from `X-Total`/`X-Total-Pages`/`X-Page`; filtering/search/sort are provider query parameters, so they apply before pagination. Linked change requests merge `closed_by`, the issue-links endpoint and inline `!N` references, deduplicated by IID, and referenced issues come from bare `#N`. 16 issue fixtures replay the whole Go flow.
- [x] 3.6 Port GitLab issue mutations and label/assignee/comment operations.
  - Closing/reopening send `state_event`, labels and assignees are set through the issue update endpoint (unassign sends an empty `assignee_ids` list) and a note is posted to `/notes` with the 201 expectation; a rejected note reports the provider status and body. No mutation is replayed against a second runtime.
- [x] 3.7 Port GitLab MR versions/diffs/discussions/replies/resolution/approval/rebase behavior.
  - `gitlab-changerequest.ts` ports the merge-request list/detail (with the per-item approval read and its optional-failure path), changed files with recomputed line stats and positioned diff lines using GitLab's line code, the versions endpoint with its `diff_refs` fallback, discussion threads (notes keep their position and resolution metadata), comment/reply/resolve, approve/unapprove, the display-name-aware approval toggle, rebase (200/202 accepted, 409 "already in progress") and the form-encoded close. The route refuses a non-feature branch and an empty result with the exact Go messages.
- [x] 3.8 Port GitLab CI job/test/log queries and retry/cancel controls/streams.
  - Pipelines (clamped limit, id-descending order), pipeline jobs, job traces as `text/plain`, the test report (mapped onto the provider summary with a flexible `system_output`, `null` for a pipeline without a report) and retry/cancel with the documented status expectations and diagnostics. 28 change-request and CI fixtures replay the whole Go flow.

## 4. AI and session services

- [x] 4.1 Port bounded Pi session discovery/JSONL parsing with malformed/oversized fixture tests.
  - `pi-sessions.ts` ports the discovery and parse: sessions are grouped by the basename of their working directory (falling back to the directory slug), the title is the first user text truncated to 57 characters plus an ellipsis or the formatted timestamp, and the creation/update time is the session timestamp in milliseconds. The parse is bounded and never executes content: a line above 1 MB abandons that file's parse, a malformed line is skipped, a file without a session header is skipped and an absent directory is an empty list. Four fixtures (`sessions`, `malformed`, `oversized-line`, `empty`) replay the Go listing against the same directory tree, plus bounds tests for the missing directory, the PATH-based executable lookup and inert content.
- [x] 4.2 Port streamed log analysis and process cancellation/error handling.
  - `ai-streams.ts` runs `pi --print --no-session --no-tools` with the 100 KB tail bound and its truncation note, a 90 second timeout, and the Go diagnostics (`pi not found in PATH` as 503, `AI analysis timed out` as 504, `pi analysis failed: …` as 502). The stream route reproduces the Go shape of buffering the output into a single `delta` event followed by `done`; an exit-0 run with no output is an empty analysis, exactly as the Go handler treated it. Cancellation and the timeout both kill the child.
- [x] 4.3 Port CR review checkout ownership and Pi RPC stream lifecycle.
  - `cr-review.ts` creates a uniquely named checkout in the system temp directory (fetch best-effort and bounded, detached `origin/<branch>` first with a local-branch fallback), writes the prompt file inside it, spawns `pi --mode rpc --no-session --tools bash,read,grep,find --thinking low` with the prompt on stdin, and maps RPC events onto deltas (text/thinking deltas, `> \`cmd\`` for a bash tool call, `> running <tool>…` otherwise) until `agent_end`. The review is bounded to five minutes, a cancelled stream kills the child, a checkout failure is reported as an SSE error naming the branch, and a silent run reports `pi error: pi produced no output`. `test/integration-ai.test.ts` drives this end to end with a scripted `pi` on PATH.
- [x] 4.4 Port scoped callback authorization and provider comment submission; test wrong target/expired token/disconnect.
  - The callback registry issues a 16-byte random token per review, registers it only for a real change request, and revokes it when the stream ends — so a disconnect makes the token unknown. A comment is posted to the session's own app and change request (never a request-supplied target), prefixed with the AI attribution, with an inline position built from the lazily fetched and cached diff version SHAs; a version or post failure answers `{ok:false,error}` rather than an HTTP error. The callback route is authorized by its path token instead of the instance capability (`isSessionAuthorizedRoute`), which the test pins together with the fact that every other route still requires the instance token; unknown, expired and wrong-provider tokens are all rejected without posting.
- [x] 4.5 Test cleanup preserves pre-existing worktrees and never persists secrets.
  - Cleanup removes only the review's own checkout and its prompt file, asserted by a test that creates a pre-existing linked worktree, runs a review and checks that the pre-existing worktree is still registered and no `cr-review-*` directory remains; the timeout path removes the prompt file as well. No secret is persisted: the callback token lives only in the in-memory registry and in the prompt file inside the owned checkout, which is deleted, and the instance capability is never handed to the agent — the test asserts the registry is empty after the stream and that the token is unusable afterwards.

## 5. Cutover and acceptance

- [x] 5.1 Switch complete route families to Bun only after fixture parity; settle old requests before changing mutation owner.
  - Every family with fixture parity is now `bun` in `LEGACY_ROUTE_OWNERSHIP` (git, providers, repos, github, gitlab, ai, system pi-sessions); the remaining families stay `go` and the same server delegates them to the private child, so the client needs no per-family base URL. The client cutover is one environment variable: `AGENTIC_DEVENV_FORWARD_URL` points the unchanged environment client's transport at the unified server (path and query preserved, instance capability added as a header), set by the shell only when it actually serves the Git capability and cleared on shutdown. A request is never sent to both runtimes: the transport rewrites the target once, and the server either answers in-process or delegates — it never does both.
- [x] 5.2 Exercise provider/issue/CR/CI/agent UI journeys through unchanged clients and record remaining Go owners.
  - `test/integration-cutover.test.ts` drives the **unchanged** `@devenv/core` client (constructed with the child's URL) through provider listing, repository search, issue list/detail/comments, change-request list, discussions, pipeline jobs, job logs and Pi sessions against the real Bun server, and asserts that an unported family (`/api/apps`) is delegated to the stub child while the migrated ones are not. Remaining Go owners are recorded in the manifest table and in `docs/integration-port.md` (`app`, `actions`, `docker`, `kubernetes`, `scripts`, `/api/events`, `/api/health`). The interactive terminal journeys themselves are not runnable headless and remain for the test-verifier.
- [x] 5.3 Run combined verification and isolated integration smoke tests; document unavailable live-provider coverage and rollback boundaries.
  - Combined verification: `biome check`, `tsc --noEmit`, `bun test` (1282 pass, the single failure being the pre-existing `shellHelp` wiki-tab timeout), `test:devenv` (169 pass), `go test ./...` and `go vet ./...` all green. Packaged smoke: `dist/agentic-coding server` started outside the source tree with a temporary `DEVENV_HOME`/`DEVENV_CONFIG_DIR`, the Go child answered `/api/health` with the spawned identity, and the Bun server answered `401` without the instance capability on both a Bun-owned and a delegated legacy route. Unavailable coverage (live provider accounts, real Pi sessions, interactive journeys) and the rollback boundary (clear the forward variable, then restore a family's owner in the manifest) are documented in `docs/integration-port.md`.
