## 4. Fix reused-agent identity refresh (quality-verifier QV-001/QV-002)

Stable naming alone let the reuse `observe` path find and re-prompt the still-running agent, but that agent's own OS process env is frozen at its original `agent start` and was never refreshed for the new generation. `workflow handoff` reads `HERDR_RUN_ID`/`HERDR_RUN_GENERATION`/`HERDR_RUN_TOKEN` exclusively from `process.env`, so the reused agent's eventual handoff used the prior, already-completed run's stale identity and was rejected as `stale-run`/`unauthorized` — the naming fix stopped the extra tab but left the follow-up round's handoff unreachable. Design.md's non-goals explicitly ruled out a new persistence mechanism, assuming name stability was sufficient; this task revises that assumption.

Reverted after the security-verifier found it persisted a plaintext bearer capability token at a path every co-located sibling role can read (SV-001/SV-002/SV-003).
- [x] 4.2 (superseded by section 5) `resolveHandoffIdentity()` marker-preferring variant in `cli.ts` — reverted along with 4.1.
- [x] 4.3 (superseded by section 5) Marker-based tests in `test/workflow-cli.test.ts`/`test/workflow-effects.test.ts` — replaced by the role-identity-based tests in section 5.
