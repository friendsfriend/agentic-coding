## 2. Server ownership and client migration

- [x] 2.1 Add Bun server composition root and lifecycle integration around the existing WorkflowApplication/Effect layer.
  - `src/server/lifecycle.ts` (`startWorkflowServer`, loopback bind, per-instance authority, owned stop), `src/server/app.ts` (transport), `agentic-coding server` starts Go + Bun and stops both on signal, TUI starts/owns the listener through the shell resource registry (`OwnedResourceKind` extended).
- [x] 2.2 Move repository coordinators and pure/read-only observation operations behind server endpoints.
  - Repository execution coordinators are triggered only through server endpoints (`/workflow/execute` and the mutation routes), and read-only observation operations are served by `/observe`, `/workflow/view` and `/api/v1/telemetry/*`. Dashboard callers use the typed client wrappers (from observations/mutations) with an in-process fallback only when no transport is configured. Validated across `test/server-api.test.ts`, `test/dash-backend-client.test.ts` and the dashboard suites.
- [x] 2.3 Move telemetry receivers/stores/watchers/retention into server ownership and expose typed query endpoints.
  - `src/server/telemetry.ts` owns the SQLite trace database, workspace scanning, retention and the file watcher; `src/server/receivers.ts` owns the OTLP/Zipkin/Datadog HTTP listeners, the gRPC helper, the Prometheus scraper and the StatsD listener, routing decoded signals into a shell-injected sink. Typed `/api/v1/telemetry/{snapshot,scan,prune}` endpoints and `telemetry.updated` events are exposed; the TUI reads via `RemoteTelemetryDb` and no longer opens SQLite, watches files or starts receivers. Validated by `test/server-telemetry.test.ts`.
- [x] 2.4 Delegate unported environment routes to private Go with cancellation and bounded response handling.
  - `/api/v1/environment/*` forwards method/path/query, the private instance token and `request.signal`, and rejects a delegated response above the bound (`src/server/app.ts`); verified in `test/server-api.test.ts`.
- [x] 2.5 Migrate workflow list/detail/artifact clients and remove direct filesystem/Git/Herdr/SQLite access from views.
  - Dashboard reads that hit backend state cross the typed client (observations, local changes/diff, wiki snapshot changes/diff, OpenSpec artifacts, verifier findings/report, developer-review findings, repair preview, change discovery, model-config reads) and mutations cross the API. View `.tsx` components no longer import backend I/O; the observation/engine/config-cache adapters are the transitional seam. Enforced by `checkViewBackendIsolation` in `test/workflow-source-layer-boundaries.test.ts` (with a negative fixture).
- [x] 2.6 Migrate workflow start/action/question/repair/config operations while preserving revisions and commit reconciliation.
  - `startWorkflow`, `runWorkflow`, `applyRepair`, `answerQuestion`, `switchWorkflowPreset`, review saves and the execution trigger cross `/api/v1/workflow/*`; `previewRepair` crosses the observation API; agent-config writes (`profileMutation`/`presetMutation`/deletes) cross `/api/v1/config/agents` via `applyAgentsMutation`, validated by `test/dash-backend-client.test.ts` and `test/dash/modelConfigModal.test.tsx`.
- [x] 2.7 Implement scoped ephemeral credential request/reply transport, timeout/disconnect cancellation and secret-redaction tests.
  - `src/server/credentials.ts` (single-owner, timeout/disconnect resolution, no persisted value), `/api/v1/credentials/respond` and the `credentialPrompt(ownerId)` bridge in `app.ts`; tests in `test/server-api.test.ts`.

## 3. Events and CLI

- [x] 3.1 Implement domain event envelope with instance/sequence/revision and bounded subscription buffering.
  - `src/server/events.ts`: `EventEnvelope`, monotonic sequence, bounded per-subscriber queue that overflows to a resync request instead of blocking the publisher; tests in `test/server-api.test.ts`.
- [x] 3.2 Add stable replay/history cursor or snapshot-resync behavior; test reconnect gaps and slow-client output recovery.
  - `EventBroker.replay` returns `snapshotRequired` for a cursor outside the retained window and the SSE route emits `event: resync`; reconnect-gap and overflow tests in `test/server-api.test.ts`.
- [x] 3.3 Migrate dashboard/telemetry subscriptions and late-result rejection without enabling background mutations from reads.
  - `src/server/subscriptions.ts` owns the Herdr subscription and per-repository execution settle/error listeners and publishes `workflow.updated`; the dashboard refreshes from the client event stream via `BackendClient.subscribe` (with a transport-less fallback for demo/tests). Telemetry subscriptions run through `RemoteTelemetryDb`; dashboard reads remain observational and late results are rejected by the existing generation/abort guards. Validated by `test/server-api.test.ts` and the dashboard suites.
  - The dashboard's explicit execution trigger now crosses the API; the Herdr event subscription and telemetry subscription migration are not done.
- [x] 3.4 Migrate supported headless CLI execution/read paths and full-feature attach with explicit server capabilities.
  - Headless reads (`--json`, `workflow status`/`projects`) and agent execution (`handoff`/`question`/`research-handoff`) cross the typed boundary. `agentic-coding attach <url> [--token TOKEN|AGENTIC_WORKFLOW_TOKEN]` is now a full-feature attach: it configures the typed client against the remote unified server, renders the workflow + observability surface, derives telemetry from the server snapshot, omits the private-Go environment feature, and states the capability surface in the header (`attachLabel`). Without a token it keeps the environment-only behavior. Validated by `test/app/appShell.test.tsx` (capability label + no Environments) and the server/client suites. Interactive developer commands (`action`, `repair`, admin) still run at the CLI's own in-process application boundary.
- [x] 3.5 Remove __dashboard-observe protocol after last consumer moves and enforce typed-client-only backend access from views.
  - The `__dashboard-observe` protocol and its `cli.ts` handler are removed and the async observation path uses the typed client. `checkViewBackendIsolation` fails any `tui/dash`/`tui/otel` `.tsx` component that imports `workflow/effects`, `workflow/execution-coordinator`, `workflow/operations`, `workflow/application`, `workflow/startup`, `backend/*`, `bun:sqlite`, `bun:ffi`, `node:fs`, `node:fs/promises` or `node:child_process`, pinned by a positive src check and a negative fixture.
