## Why

The centralized OKF bundle already serves multiple projects, but the existing `repository/*` concept IDs and sparse instructions make project-specific facts look globally applicable. Explicit project/shared namespaces and migration guidance will prevent cross-project ambiguity without adding another wiki root, frontmatter field, or CLI abstraction.

## What Changes

- Extend the `knowledge-wiki` requirements with an explicit namespace convention: `projects/<project-id>/<concept>` for project-specific knowledge and `shared/<concept>` only for facts evidenced across the projects they cover.
- Require planning, fusion-planning, fusion-consolidation, and archive guidance to choose namespaces deliberately, interpret repository-relative sources in the documented project's context, update concepts in place, and avoid duplicate active concepts.
- Clarify that the existing centralized bundle remains the default and that OKF does not require one repository per bundle or automatic multi-root federation.
- Document the same convention in the README without changing wiki CLI operations or their existing root-resolution behavior.
- Migrate the eight current `repository/*` Agentic Coding drafts to `projects/agentic-coding/*` by preserving their frontmatter, sources, bodies, draft status, and repository citations; if legacy paths must remain for compatibility, leave them as explicitly deprecated redirects rather than active duplicates.
- Keep all migrated concepts unverified; do not add human or machine verification events.
- Add focused checks for namespace guidance, contradictory single-repository claims, unchanged CLI behavior, and migration preservation.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `knowledge-wiki`: Define project-scoped and shared concept namespaces, source-context and evidence rules, and safe migration/update behavior while preserving the centralized bundle and current command surface.
