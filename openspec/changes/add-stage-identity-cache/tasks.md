## 2. Capture and reuse

- [x] 2.0 Spike (write the result into design.md D2 before 2.1): does the Playwright driver expose the `Authorization` request header of a native basic-auth dialog login (`request.allHeaders()`)? If not, document the Basic hand-off as non-cacheable and skip 2.4. — **Result: not observable.** The driver sees a navigation's status and a context's cookies, not the dialog's generated header, so `http-basic` is documented as non-cacheable (design.md D2, spec scenario "Basic login the driver cannot observe", `docs/agent-environments.md`) and 2.4 is dropped.
- [x] 2.1 `pool.ts`: after a stage session's login success (automated or developer hand-off), periodically (`identityCache.refreshSeconds`) and on clean close, capture the cookies, localStorage and sessionStorage of the stage's application and login origins only (nothing from other hosts); replace the entry with each capture; tests with the fake driver (JWT in sessionStorage, in localStorage, in an HttpOnly cookie; third-party origin ignored; rotated refresh token replaces the old). — The refresh is bound to use (the first browser call past the interval) rather than a timer; `test/browser-stage-identity.test.ts` covers capture after a login, after a `stage_login` that reused a cached identity, on clean close, and on a refresh; the third-party origin and the per-origin scoping are asserted.
- [x] 2.2 Install the cached state into a new stage session's context before the first navigation (cookies via the server-internal `addCookies`, storage via an origin-scoped init script); evict the entry when the success condition fails after a cache install and continue with the normal login path; tests (silent reuse, rejected cookie evicts and falls through, expired entry not installed, other stage/role untouched). — `browser_open({ stage, stageApp, stageRole })` names the role; an unknown role is `stage-role-unknown`. A rejected entry is evicted and the ordinary login runs (and its own declared condition decides).
- [x] 2.3 Journal/result: the login result and the first journal step record `identity: "cache" | "recipe" | "user"`; add every cached value (and token-shaped substring) to the session's redactor secret set; a mid-run recreated session continues from the latest capture; test that no response, telemetry line or log contains a cookie value. — The result carries `identity`; the journal step that consumes it belongs to `add-stage-test-workflow`/`-launch` (recorded in design.md D6/risks), because those changes own the step and would otherwise duplicate the field. Redaction: the store's `secrets()` joins the browser routes' redaction secrets (plain and URL-encoded) and the identity route passes through the same redactor; "every browser reply is scrubbed with the cached values" and "the store, its serialisation and the log lines carry no value" assert it.
- [x] 2.4 Basic credential: capture from the browser's `Authorization: Basic` header after a developer-typed dialog login and re-install it as origin-scoped HTTP credentials sent only on `401`; tests (typed once, reused next run, never sent to another origin, evicted on a `401` after install). — **Skipped, per 2.0's legitimate outcome**: the header is not observable, so there is nothing to capture. The configured `http-basic` path installs its credential per session, unchanged.

## 3. Forgetting and surfaces

- [x] 3.1 Stage route `identity` list/forget (value-free), CLI `stage identity list|forget`, dashboard stage action; tests. — `GET /api/v1/stages/identity`, `POST /api/v1/stages/identity/forget` (`src/server/stages/routes.ts`), `agentic-coding stage identity list|forget [--stage S] [--role R] [--all] [--json]` (`src/server/stages/command.ts`), Settings → Stages rows (`src/tui/settings/items.ts`, `App.tsx` action `stage-identity-forget`); tests in `test/browser-stage-identity.test.ts`.
- [x] 3.2 Prove the memory-only rule: a test that the workflow store, snapshots, `telemetry.jsonl`, evidence and a heap-diagnostic dump contain no cached value; a server restart yields an empty cache. — The cache has no writer: no store row, no snapshot field, no `telemetry.jsonl` line, no evidence file, and `list()`/`toJSON`/`toString` cannot express a value (asserted, plus "a fresh process has an empty cache: nothing was written anywhere"). A V8 heap snapshot is memory and cannot be proven empty of it; design.md D6 states that limit instead of implying a guarantee.
